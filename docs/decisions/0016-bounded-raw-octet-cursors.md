# Decision 0016: Raw octet cursor copies are bounded and transactional

Status: accepted implementation prerequisite

Date: 2026-08-23

## Context

Generated byte-field construction needs to copy an explicitly bounded prefix
between an application value and caller-provided wire storage. The existing
cursor API could reserve and lend extents but had no allocation-free primitive
for a regular constructing decode. Array conversion is inappropriate because
wire octet arrays deliberately share `Ada.Streams.Stream_Element_Array`.

## Decision

Profile 1 provides `Read_Octets` and `Write_Octets` over the existing octet
array subtype. Both operations accept an explicit `Octet_Count`, use the
prefix of the supplied application array, and support arbitrary Ada array
lower bounds.

The operations check the complete source and destination bounds before copying
any octet. A failed read leaves both its cursor and destination unchanged. A
failed write leaves both its cursor and output unchanged. Zero count succeeds
without observing an array element.

`Read_Octets` distinguishes a short wire extent (`Truncated`) from a short
application destination (`Destination_Too_Small`). `Write_Octets` reports
`Destination_Too_Small` for either short source or destination. Generated
code must establish its schema and binding bounds before calling either
primitive, so destination capacity failure is an adapter-contract outcome,
not malformed writer input.

## Consequences

- Constructing decoders can populate definite bounded byte arrays without
  allocation, overlays, access values, or intermediate array conversion.
- Callers can prove failure atomicity from cursor position and unchanged
  storage.
- Borrowed observers continue to use `Visit_Extent`; copying and borrowing
  remain distinct contracts.
- The primitive does not add a streaming decoder or retain any payload
  reference.
